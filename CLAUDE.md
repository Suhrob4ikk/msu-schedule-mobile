# МГУ Расписание — мобильное приложение (Android)

Расписание занятий филиала МГУ в Душанбе. React Native + Expo, раздаётся **APK по прямой
ссылке** (не в Google Play). Пользователей ~20–30 студентов.

Язык общения с пользователем — **русский**. Владелец проекта не всегда технический:
объясняй простыми словами, делай сам, не проси подтверждений на мелочи.

⚠️ **Путь до проекта не должен содержать кириллицу.** Компилятор Android NDK не собирает
нативный код из пути вроде `Desktop\Проекты\...` — падает на кодировке. Папка специально
лежит в `C:\Users\Suhrob\Desktop\msu-schedule-mobile\`. Не переносить.

## Связь с остальным проектом

Приложение **ничего не парсит само** — только рисует ответы API. Бэкенд и сайт живут в
отдельном репозитории `Suhrob4ikk/msu-schedule`, там же основной `CLAUDE.md` с описанием
данных, парсера и панели разработчика. Если данные на экране неверные — почти всегда
чинить надо в бэкенде, а не здесь.

- Бэкенд: https://msu-schedule.onrender.com — **но приложение ходит туда не напрямую**,
  см. «Почему API через сайт» ниже
- Сайт: https://frontend-ten-nu-80.vercel.app
- Ветка этого репозитория — **`master`** (не `main`). Репозиторий **публичный**: это нужно,
  чтобы APK скачивался по прямой ссылке без входа в GitHub.

## Адреса — одно место

`app.json` → `expo.extra`:

```json
"apiUrl": "https://frontend-ten-nu-80.vercel.app/backend",
"webUrl": "https://frontend-ten-nu-80.vercel.app"
```

Читаются через `expo-constants` в `src/api.ts` (`API_BASE`), `src/profile/ProfileScreen.tsx` и
`src/InviteCard.tsx` (`WEB_URL`).
Литералы в коде — только как страховка. Менять адрес — правкой `app.json`, а не поиском по файлам.

### ⚠️ Почему API через сайт, а не напрямую на Render

**Megafon TJ (мобильный интернет) молча роняет пакеты до IP-диапазона Render
`216.24.57.0/24`.** Проверено 31 августа 2026 на телефоне при выключенном Wi-Fi:
не открывается ни `msu-schedule.onrender.com`, ни голый IP `216.24.57.7` (значит,
дело не в DNS и не в имени хоста), ни любой чужой сервис на `onrender.com` — везде
`ERR_CONNECTION_TIMED_OUT`. Через VPN всё работает, на Wi-Fi работает, IPv6 ни при чём.
Именно поэтому приложение годами работало на Wi-Fi и не работало на мобильном интернете.

Vercel лежит в другом диапазоне IP, его Megafon пропускает. Сайт перекидывает
`/backend/*` на `https://msu-schedule.onrender.com/api/*` (правило — в
`frontend/next.config.ts` репозитория бэкенда) и достукивается до Render со своей
стороны, где блокировки нет.

**Не возвращайте `apiUrl` на прямой адрес `onrender.com`.** Ретраи и длинные
тайм-ауты тут бессильны — пробовали в v1.9.18 и v1.9.19, оба раза мимо: пакеты
не доходят, сколько ни повторяй.

## Оформление: «Внешний вид» (окт 2026, с 1.9.40)

По ТЗ «токены и экран „Внешний вид“». Метка git до начала — **`before-appearance`**.

- Все вкладки берут цвета из одних токенов (`src/schedule/colors.ts`): прежние экраны — через
  `useTheme()`, где старые имена (`fg`, `muted`, `primary`…) теперь указывают на токены.
  Поэтому выбор пользователя действует везде сразу, без перезапуска.
- Настройки — один ключ `appearance` в AsyncStorage: акцент (8 пресетов или свой цвет),
  оттенки типов занятий (голубой/сиреневый/янтарный/мятный), фон (система/светлый/тёмный/
  чёрный), плотность (обычная/компактная). Корневой `_layout` ждёт их и шрифт Onest до первого
  кадра — без мигания.
- **Перенос**: если ключа нет — читаются `msu_theme` и `msu_accent` (до 1.9.40): тема → фон,
  green → изумруд, violet → фиолетовый, blue или ничего → синий. Старые ключи не стираются.
- `on-accent`: ТЗ обещает, что белый или #0B0D12 всегда дают ≥ 4,58 : 1 — для средне-серых
  это неверно (#777777: 4,48). Запасной вариант — чистый чёрный, он гарантирует ≥ 4,5.
- Пресеты (утверждены владельцем 4 окт 2026): синий #2F62EA, фиолетовый #7357F0, изумруд
  #0E9B72, бирюзовый #0E8FA6, розовый #D6407F, оранжевый #E8640C, жёлтый #F2C230, графит #4D5566.
- Контраст проверяется временным скриптом на всех трёх фонах (`node --experimental-strip-types`
  с загрузчиком, добавляющим `.ts` к относительным импортам) — потому `colors.ts` и
  `appearanceModel.ts` без импортов React Native.
- Шрифт прежних вкладок — `src/OnestText.tsx`: импорт `Text`/`TextInput` оттуда, а не из
  `react-native`. Начертание берётся из `fontWeight`, вёрстка не меняется.
- Виджет на рабочем столе и строка «идёт пара» (Kotlin) остаются в своих цветах.
- **Применение в два шага** (`src/appearance.ts`): «выбранное» меняется сразу (кольцо выбора
  на экране), «применённое» — следующим кадром; быстрые тапы схлопываются, запись в хранилище
  одна, через 400 мс. Смена фона — сразу (`immediate`), у неё своё растворение (ThemeReveal).
- **`freezeOnBlur: true`** у вкладок: скрытая вкладка не перерисовывается, пока её не откроют.
  Иначе смена акцента перекрашивала разом все открытые вкладки.
- **Экран «Внешний вид» без измерений раскладки.** В 1.9.40 предпросмотр брал высоту из
  `onLayout` → `setState`, внутри тикал отсчёт и пульсировала точка — владелец видел, как
  экран мелко дрожит. Теперь размеры — целые числа из ширины окна, высота карточки —
  константа, карточка неподвижна (`stillAt` у `FocusCard`), шрифт внутри не масштабируется
  (`FixedFontScale`). Не возвращать `onLayout` → `setState` в предпросмотр.
- «Свой цвет» — квадрат насыщенность × яркость и ползунок оттенка (`src/settings/ColorPicker.tsx`,
  react-native-svg + PanResponder). При перетаскивании меняется только состояние листа.
- **Плотность**: по ТЗ компактная была 52/7 против 60/10, но высоту строки пары задаёт
  содержимое (три строки в колонке времени), и разница выходила ~8 %. Сейчас:

  | | обычная | компактная |
  |---|---|---|
  | строка пары (предмет в одну строку) | 74 dp | 52 dp (поля 4, «11:15 · II» одной строкой) |
  | строка аудитории | 56 dp | 48 dp (минимум зоны нажатия) |
  | зазоры между днями / под заголовком дня / между блоками | 8 / 8 / 8 | 4 / 4 / 4 |

## Сборка APK

```bash
cd "C:/Users/Suhrob/Desktop/msu-schedule-mobile/android"
export JAVA_HOME="C:/Program Files/Android/Android Studio/jbr"
export ANDROID_HOME="C:/Android/SDK"
export PATH="$JAVA_HOME/bin:$PATH"
./gradlew assembleRelease --no-daemon
```

Готовый файл: `android/app/build/outputs/apk/release/app-release.apk` (~40 МБ, только arm64).
Копировать на рабочий стол как `МГУ Расписание vX.Y.Z.apk`.

Для эмулятора нужен x86_64: добавить `-PreactNativeArchitectures=arm64-v8a,x86_64`
(сборка дольше, файл больше — для раздачи людям так не собирать).

⚠️ **`android/app/debug.keystore` — ключ подписи, лежит только на этом компьютере**
(`android/` не в репозитории). Потеря ключа = обновления перестанут вставать поверх
установленного приложения: Android откажется ставить APK с другой подписью, всем придётся
удалять приложение и терять данные. Файл обязательно бэкапить.

## Публикация релиза

```bash
gh release create v1.7.1 "путь/к.apk" --repo Suhrob4ikk/msu-schedule-mobile --title "v1.7.1" --notes "что изменилось"
```

Дальше всё само: бэкенд читает последний релиз через `/api/app/version`, приложение
сравнивает со своей версией и показывает внизу карточку «Доступно обновление» с кнопкой
«Скачать». Проверка идёт при запуске **и при каждом возврате в приложение**, кэш 5 минут —
уведомление доходит за минуты.

Раньше проверка была только при холодном старте с часовым кэшем, и уведомление не приходило
сутками: Android держит приложение в памяти, а открытие из списка недавних экран не пересоздаёт.

## Пропуски и заметки

Замок «с 1 сентября» убран (окт 2026). Функции выключены, пока пользователь сам
не включит их в Кабинете (карточка «Учёба») — так задумано.

- **Пропуски** — отмечается только пропущенное; нет отметки у прошедшей пары = «был».
  Кнопка только у уже прошедших пар, на экзаменах и зачётах не показывается.
- **Заметки** — по умолчанию повторяются каждую неделю на этом слоте, галочкой можно
  сделать разовыми на конкретную дату.

Данные лежат **только на устройстве** (AsyncStorage), на сервер не уходят: переустановил
приложение — данных нет, синхронизации с сайтом тоже нет.

## Уведомления

Три независимых вида, у каждого свой переключатель и свой канал Android:

- **Зачёты и экзамены** — накануне в 20:00 и в день в 07:00. По умолчанию включено.
- **За 10 минут до пары** — с предметом и аудиторией. **По умолчанию выключено**: это
  уведомления по несколько раз в день, включать их за человека нельзя. Без звука, только вибрация.
- **Строка «идёт пара»** — постоянная, с отсчётом до конца пары. Тоже **выключена по
  умолчанию**: висящее уведомление без спроса навязчиво. Устройство — ниже.

Первые два пересобираются при каждой загрузке расписания; прошедшие пары пропускаются.
Отменять всегда только «свои» — по полю `data.type` (`exam` / `lesson`).

## Строка «идёт пара» (`modules/live-lesson/`)

Локальный нативный модуль на Kotlin. Показывает текущую пару с живым отсчётом, а на
**Android 16** просится отдельной плашкой прямо в статус-бар (флаг
`FLAG_PROMOTED_ONGOING` + `setShortCriticalText`; на старых версиях эти вызовы
пропускаются по `Build.VERSION.SDK_INT >= 36`, иначе был бы `NoSuchMethodError`).

Почему работает без запущенного приложения:

- расписание уже лежит в AsyncStorage под ключом `widget_data` (пишет `src/widgetData.ts`
  для виджета) — Kotlin читает базу `RKStorage` напрямую;
- отсчёт рисует сам Android (`setUsesChronometer` + `setChronometerCountDown`), поэтому
  раз в минуту будить приложение не нужно;
- будильник ставится ровно на границу пары — 5–10 раз в день, через `setWindow`
  (а не `setExact`: точные будильники на Android 12+ требуют отдельного разрешения,
  которое пользователь может отобрать);
- после перезагрузки телефона и обновления приложения будильник переподнимает
  `LiveLessonReceiver` (`BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`);
- страховка от Doze — `refreshLiveLesson()` при каждом возврате в приложение (`_layout.tsx`).

⚠️ **Копировать в `android/` не нужно.** Модуль подхватывает автолинковка
(`useExpoModules()` в `settings.gradle`), а манифест библиотеки склеивается с манифестом
приложения сам — `expo prebuild` его не стирает. В этом его отличие от виджета.

В `modules/live-lesson/android/build.gradle` обязательны `versionCode` и `versionName`
внутри `defaultConfig` — без них конфигурация Gradle падает с
«android.defaultConfig.versionName is not defined».

Виджет и эта строка кормятся **только текущей неделей и только своей группой** — иначе
достаточно было заглянуть в архив или в расписание другой группы, чтобы они показывали
чужое (см. `feedDevice` в `src/schedule/ScheduleScreen.tsx`).

## Проверка

```bash
npx tsc --noEmit
```

Реального расписания в июле-августе нет (на msu.tj пустой файл), вживую проверить перемены,
окна и «на сегодня всё» не получится. Логику в таких случаях проверять временным скриптом
на синтетических данных, а вёрстку — на эмуляторе:

```bash
C:/Android/SDK/emulator/emulator.exe -avd Medium_Phone_API_36.0 -gpu swiftshader_indirect
adb install -r <apk>
adb exec-out screencap -p > out.png
```

На эмулятор нужен APK с x86_64. Эмулятор медленный: белый экран первые ~20 секунд после
запуска приложения — это нормально, не краш.

## Кэш и сеть

**Экраны рисуются из кэша, потом молча обновляются.** Раньше было наоборот: сначала
запрос, и только когда он упадёт (15 секунд тайм-аута, а на спящем Render дольше) —
чтение с диска. Пользователь смотрел на спиннер, хотя данные уже лежали в AsyncStorage.

Ключи AsyncStorage — те же, что заполняет полная синхронизация (`syncService.ts`),
поэтому кэш общий и заполняется заранее:

| Ключ | Что |
|---|---|
| `cache_groups`, `cache_weeks_all`, `cache_weeks_<groupId>` | списки |
| `cache_schedule_<groupId>_<weekId>` | расписание группы |
| `cache_teachers_<weekStart>`, `cache_teacher_<id>_<weekStart>` | преподаватели |
| `cache_rooms_<day>_<pair>_<weekStart>` | свободные аудитории |
| `cache_changes_<groupId|all>` | лента изменений |

- Полная синхронизация — **один** запрос `/api/schedule/bulk-sync`, стартует через
  3 секунды после запуска, чтобы не отбирать канал у первого экрана.
- `src/api.ts` дедуплицирует одинаковые пути: три экрана, спросившие список групп
  одновременно, дают один запрос.
- **Состояние сети — событие от Android** (`@react-native-community/netinfo`,
  `NET_CAPABILITY_VALIDATED`), своих запросов ноль. `reachabilityUrl` в
  `SyncContext.tsx` — только запасной путь, если система не дала ответа.
- Неделя «прилипает» к выбранной пользователем только после того, как он сам нажал
  кнопку недели (`userPickedWeekRef`). Иначе неделя всегда пересчитывается по
  сегодняшней дате — чтобы кэш недельной давности не удерживал экран на прошлой неделе.

## Известные слабые места

- В `app.json` не заявлен плагин `expo-notifications`, хотя пакет используется — иконка
  и цвет уведомлений на Android остаются системными.
- `netinfo` — нативный модуль: правки в `SyncContext` не подхватятся в уже установленном
  APK, нужна пересборка (`expo prebuild` + `assembleRelease`).
