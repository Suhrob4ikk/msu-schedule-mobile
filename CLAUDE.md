# МГУ Расписание — мобильное приложение (Android)

Расписание занятий филиала МГУ в Душанбе. React Native + Expo, раздаётся **APK по прямой
ссылке** (не в Google Play). Пользователей ~20–30 студентов.

Язык общения с пользователем — **русский**. Владелец проекта не всегда технический:
объясняй простыми словами, делай сам, не проси подтверждений на мелочи.

⚠️ **Путь до проекта не должен содержать кириллицу.** Компилятор Android NDK не собирает
нативный код из пути вроде `Desktop\Проекты\...` — падает на кодировке. Папка специально
лежит в `C:\Users\Suhrob\Desktop\msu-schedule-mobile\`. Не переносить.

## Связь с остальным проектом

Приложение **ничего не парсит само** — только рисует ответы API. Бэкенд и сайт живут в
отдельном репозитории `Suhrob4ikk/msu-schedule`, там же основной `CLAUDE.md` с описанием
данных, парсера и панели разработчика. Если данные на экране неверные — почти всегда
чинить надо в бэкенде, а не здесь.

- Бэкенд: https://msu-schedule.onrender.com
- Сайт: https://frontend-ten-nu-80.vercel.app
- Ветка этого репозитория — **`master`** (не `main`). Репозиторий **публичный**: это нужно,
  чтобы APK скачивался по прямой ссылке без входа в GitHub.

## Адреса — одно место

`app.json` → `expo.extra`:

```json
"apiUrl": "https://msu-schedule.onrender.com/api",
"webUrl": "https://frontend-ten-nu-80.vercel.app"
```

Читаются через `expo-constants` в `src/api.ts` (`API_BASE`) и `app/profile.tsx` (`WEB_URL`).
Литералы в коде — только как страховка. Менять адрес — правкой `app.json`, а не поиском по файлам.

## Версия — три места сразу

При каждом релизе поднимать во всех трёх, иначе разъедется:

1. `android/app/build.gradle` — `versionCode` (+1) и `versionName`
2. `app.json` — `expo.version` (по нему приложение сравнивает себя с последним релизом)
3. `app/profile.tsx` — текст версии внизу экрана

⚠️ `android/` в `.gitignore`, поэтому `versionCode` живёт **только на компьютере владельца**.

## Сборка APK

```bash
cd "C:/Users/Suhrob/Desktop/msu-schedule-mobile/android"
export JAVA_HOME="C:/Program Files/Android/Android Studio/jbr"
export ANDROID_HOME="C:/Android/SDK"
export PATH="$JAVA_HOME/bin:$PATH"
./gradlew assembleRelease --no-daemon
```

Готовый файл: `android/app/build/outputs/apk/release/app-release.apk` (~40 МБ, только arm64).
Копировать на рабочий стол как `МГУ Расписание vX.Y.Z.apk`.

Для эмулятора нужен x86_64: добавить `-PreactNativeArchitectures=arm64-v8a,x86_64`
(сборка дольше, файл больше — для раздачи людям так не собирать).

⚠️ **`android/app/debug.keystore` — ключ подписи, лежит только на этом компьютере**
(`android/` не в репозитории). Потеря ключа = обновления перестанут вставать поверх
установленного приложения: Android откажется ставить APK с другой подписью, всем придётся
удалять приложение и терять данные. Файл обязательно бэкапить.

## Публикация релиза

```bash
gh release create v1.7.1 "путь/к.apk" --repo Suhrob4ikk/msu-schedule-mobile --title "v1.7.1" --notes "что изменилось"
```

Дальше всё само: бэкенд читает последний релиз через `/api/app/version`, приложение
сравнивает со своей версией и показывает внизу карточку «Доступно обновление» с кнопкой
«Скачать». Проверка идёт при запуске **и при каждом возврате в приложение**, кэш 5 минут —
уведомление доходит за минуты.

Раньше проверка была только при холодном старте с часовым кэшем, и уведомление не приходило
сутками: Android держит приложение в памяти, а открытие из списка недавних экран не пересоздаёт.

## Функции, открывающиеся 1 сентября 2026

`src/features.ts`, дата читается как местное время устройства — замок снимается сам,
без обновления приложения. **Но** функции остаются выключенными, пока пользователь сам
не включит их в «Моём кабинете» — так задумано.

Флаг блокировки **нельзя** выносить в константу уровня модуля: она вычисляется один раз при
старте, а Android держит приложение в памяти сутками — кабинет показывал бы «закрыто»
и после наступления даты. Проверять внутри компонента.

- **Пропуски** — отмечается только пропущенное; нет отметки у прошедшей пары = «был».
  Кнопка только у уже прошедших пар, на экзаменах и зачётах не показывается.
- **Заметки** — по умолчанию повторяются каждую неделю на этом слоте, галочкой можно
  сделать разовыми на конкретную дату.

Данные лежат **только на устройстве** (AsyncStorage), на сервер не уходят: переустановил
приложение — данных нет, синхронизации с сайтом тоже нет.

## Уведомления

Три независимых вида, у каждого свой переключатель и свой канал Android:

- **Зачёты и экзамены** — накануне в 20:00 и в день в 07:00. По умолчанию включено.
- **За 10 минут до пары** — с предметом и аудиторией. **По умолчанию выключено**: это
  уведомления по несколько раз в день, включать их за человека нельзя. Без звука, только вибрация.
- **Строка «идёт пара»** — постоянная, с отсчётом до конца пары. Тоже **выключена по
  умолчанию**: висящее уведомление без спроса навязчиво. Устройство — ниже.

Первые два пересобираются при каждой загрузке расписания; прошедшие пары пропускаются.
Отменять всегда только «свои» — по полю `data.type` (`exam` / `lesson`).

## Строка «идёт пара» (`modules/live-lesson/`)

Локальный нативный модуль на Kotlin. Показывает текущую пару с живым отсчётом, а на
**Android 16** просится отдельной плашкой прямо в статус-бар (флаг
`FLAG_PROMOTED_ONGOING` + `setShortCriticalText`; на старых версиях эти вызовы
пропускаются по `Build.VERSION.SDK_INT >= 36`, иначе был бы `NoSuchMethodError`).

Почему работает без запущенного приложения:

- расписание уже лежит в AsyncStorage под ключом `widget_data` (пишет `src/widgetData.ts`
  для виджета) — Kotlin читает базу `RKStorage` напрямую;
- отсчёт рисует сам Android (`setUsesChronometer` + `setChronometerCountDown`), поэтому
  раз в минуту будить приложение не нужно;
- будильник ставится ровно на границу пары — 5–10 раз в день, через `setWindow`
  (а не `setExact`: точные будильники на Android 12+ требуют отдельного разрешения,
  которое пользователь может отобрать);
- после перезагрузки телефона и обновления приложения будильник переподнимает
  `LiveLessonReceiver` (`BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`);
- страховка от Doze — `refreshLiveLesson()` при каждом возврате в приложение (`_layout.tsx`).

⚠️ **Копировать в `android/` не нужно.** Модуль подхватывает автолинковка
(`useExpoModules()` в `settings.gradle`), а манифест библиотеки склеивается с манифестом
приложения сам — `expo prebuild` его не стирает. В этом его отличие от виджета.

В `modules/live-lesson/android/build.gradle` обязательны `versionCode` и `versionName`
внутри `defaultConfig` — без них конфигурация Gradle падает с
«android.defaultConfig.versionName is not defined».

Виджет и эта строка кормятся **только текущей неделей и только своей группой** — иначе
достаточно было заглянуть в архив или в расписание другой группы, чтобы они показывали
чужое (см. `app/index.tsx`, условие перед `writeWidgetData`).

## Проверка

```bash
npx tsc --noEmit
```

Реального расписания в июле-августе нет (на msu.tj пустой файл), вживую проверить перемены,
окна и «на сегодня всё» не получится. Логику в таких случаях проверять временным скриптом
на синтетических данных, а вёрстку — на эмуляторе:

```bash
C:/Android/SDK/emulator/emulator.exe -avd Medium_Phone_API_36.0 -gpu swiftshader_indirect
adb install -r <apk>
adb exec-out screencap -p > out.png
```

На эмулятор нужен APK с x86_64. Эмулятор медленный: белый экран первые ~20 секунд после
запуска приложения — это нормально, не краш.

## Известные слабые места

- `SyncContext` пингует `/api/schedule/groups` каждые 15 секунд ради проверки сети —
  расточительно, лучше `@react-native-community/netinfo`.
- Полная офлайн-синхронизация делает сотни запросов подряд; напрашивается bulk-эндпоинт.
- В `app.json` не заявлен плагин `expo-notifications`, хотя пакет используется — иконка
  и цвет уведомлений на Android остаются системными.
