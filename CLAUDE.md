# МГУ Расписание — мобильное приложение (Android)

Расписание занятий филиала МГУ в Душанбе. React Native + Expo, раздаётся **APK по прямой
ссылке** (не в Google Play). Пользователей ~20–30 студентов.

Язык общения с пользователем — **русский**. Владелец проекта не всегда технический:
объясняй простыми словами, делай сам, не проси подтверждений на мелочи.

⚠️ **Путь до проекта не должен содержать кириллицу.** Компилятор Android NDK не собирает
нативный код из пути вроде `Desktop\Проекты\...` — падает на кодировке. Папка специально
лежит в `C:\Users\Suhrob\Desktop\msu-schedule-mobile\`. Не переносить.

## Связь с остальным проектом

Приложение **ничего не парсит само** — только рисует ответы API. Бэкенд и сайт живут в
отдельном репозитории `Suhrob4ikk/msu-schedule`, там же основной `CLAUDE.md` с описанием
данных, парсера и панели разработчика. Если данные на экране неверные — почти всегда
чинить надо в бэкенде, а не здесь.

- Бэкенд: https://msu-schedule.onrender.com — **но приложение ходит туда не напрямую**,
  см. «Почему API через сайт» ниже
- Сайт: https://frontend-ten-nu-80.vercel.app
- Ветка этого репозитория — **`master`** (не `main`). Репозиторий **публичный**: это нужно,
  чтобы APK скачивался по прямой ссылке без входа в GitHub.

## Адреса — одно место

`app.json` → `expo.extra`:

```json
"apiUrl": "https://frontend-ten-nu-80.vercel.app/backend",
"webUrl": "https://frontend-ten-nu-80.vercel.app"
```

Читаются через `expo-constants` в `src/api.ts` (`API_BASE`) и `src/profile/ProfileScreen.tsx` (`WEB_URL`).
Литералы в коде — только как страховка. Менять адрес — правкой `app.json`, а не поиском по файлам.

### ⚠️ Почему API через сайт, а не напрямую на Render

**Megafon TJ (мобильный интернет) молча роняет пакеты до IP-диапазона Render
`216.24.57.0/24`.** Проверено 31 августа 2026 на телефоне при выключенном Wi-Fi:
не открывается ни `msu-schedule.onrender.com`, ни голый IP `216.24.57.7` (значит,
дело не в DNS и не в имени хоста), ни любой чужой сервис на `onrender.com` — везде
`ERR_CONNECTION_TIMED_OUT`. Через VPN всё работает, на Wi-Fi работает, IPv6 ни при чём.
Именно поэтому приложение годами работало на Wi-Fi и не работало на мобильном интернете.

Vercel лежит в другом диапазоне IP, его Megafon пропускает. Сайт перекидывает
`/backend/*` на `https://msu-schedule.onrender.com/api/*` (правило — в
`frontend/next.config.ts` репозитория бэкенда) и достукивается до Render со своей
стороны, где блокировки нет.

**Не возвращайте `apiUrl` на прямой адрес `onrender.com`.** Ретраи и длинные
тайм-ауты тут бессильны — пробовали в v1.9.18 и v1.9.19, оба раза мимо: пакеты
не доходят, сколько ни повторяй.

  настоящих 40, из них 38 — физкультура на стадионе.
- Аудитория в строке Расписания передаёт `day`, `pair`, `room`, `week_start` —
  экран сразу открывает её лист.
- **Стрелки ‹ › под поиском** (2.0.3, просьба владельца): соседняя пара без листа «Когда»,
  подпись — «III пара» или «чт · I» (`stepSlot`, `stepLabel`): после V — I следующего учебного
  дня, воскресенье пропускается, за пределы этой … последней опубликованной недели — бледная.
  Между ними — «Сейчас», если выбрано вручную (строка «Свободно N из M» убрана: то же в заголовке
  секции).
- **Плитки по умолчанию** (2.0.2, решение владельца): 3 в ряд (4 от 400 dp), номер и одна
  строка «до 11:30» / «весь день» / «до 15:30», фон `roomFreeBg` / `roomBusyBg`, накладка —
  янтарная точка, именная аудитория — на две клетки. Кнопка рядом с поиском переключает на
  список строк; выбор — ключ `rooms_view` (`tiles` / `list`). Подробности — в листе аудитории.

по метке `v2.0.0`).

| Файл | Что делает |
|---|---|
| `state.ts` | **чистые функции**: поиск (ё=е, таджикские буквы, начало любого слова), похожая фамилия (Левенштейн ≤ 2), буквы, статус в списке, неделя педагога, раскрытая карточка, пустые состояния |

- **Список** — объединение педагогов этой и следующей недели (`/schedule/teachers?week_start=…`),
  по id, без склейки похожих имён (дубли вроде «Б.С» / «Б.С.» — забота парсера).
- **Статусы строк** считаются на телефоне из кэша `cache_teacher_<id>_<неделя>` (его заполняет
  bulk-sync) одним `multiGet`, без запросов. Нет кэша — строка без статуса. Раз в минуту
  пересчитываются только видимые строки (`statusStore`: окно прокрутки + места строк в ref).
- **«А–Я»** — ScrollView с липкими заголовками и запомненными местами заголовков, а не
  `SectionList.scrollToLocation`: надёжно при строках разной высоты.
- **Строка пары**: пары одного слота с тем же предметом, типом и аудиторией — одна строка с
  несколькими чипами групп; разные предметы в одном слоте (физкультура 1 и 2 курса) — две
  строки. Соседние слоты с теми же предметом, типом, аудиторией и группами склеиваются.
- **Имя в шапке** (2.0.3, просьба владельца): крупное имя уехало вверх — то же имя проступает
  рядом с «←» (прозрачность от `scrollY`, нативный драйвер).
- **Раскрытая карточка**: идёт → перемена (до начала ≤ 60 мин и сегодня уже была пара) →
  спокойная «через …» (отсчёт только на сегодня и завтра).
- **Неделя по умолчанию**: в воскресенье и в субботу после последней пары педагога —
  следующая, если опубликована (решение владельца, как в «Расписании»).
- **Переходы**: чип группы → «Расписание» (`group`, `week_start`, `back=teachers`), аудитория →
  «Аудитории» (`day`, `pair`, `room`, `week_start`, `back=teachers`). Системная «Назад» там
  возвращает к педагогу (`useBackTo`, отметка гаснет при уходе с вкладки). ФИО в Расписании

## Оформление: «Внешний вид» (окт 2026, с 1.9.40)

По ТЗ «токены и экран „Внешний вид“». Метка git до начала — **`before-appearance`**.

- Все вкладки берут цвета из одних токенов (`src/schedule/colors.ts`): прежние экраны — через
  `useTheme()`, где старые имена (`fg`, `muted`, `primary`…) теперь указывают на токены.
  Поэтому выбор пользователя действует везде сразу, без перезапуска.
- Настройки — один ключ `appearance` в AsyncStorage: акцент (8 пресетов или свой цвет),
  оттенки типов занятий (голубой/сиреневый/янтарный/мятный или свой цвет — с 2.0.2), фон
  (система/светлый/тёмный/чёрный), плотность (обычная/компактная).
- **Свой цвет типа занятий** (2.0.2): `types[тип] = 'custom'` + `typesCustom[тип] = '#RRGGBB'`
  (свой цвет запоминается, как у акцента). `resolveTypes()` подставляет код в `buildTokens`;
  пара бейджа — по правилу мятного: фон = смесь с surface, текст доведён до 4,5 : 1
  (`shadePair`, проверено скриптом на 216 цветах × 3 фона). Лист «Свой цвет» общий для
  акцента и типов (`ColorTarget`), предпросмотр подменяет только цвета этого типа. Корневой `_layout` ждёт их и шрифт Onest до первого
  кадра — без мигания.
- **Перенос**: если ключа нет — читаются `msu_theme` и `msu_accent` (до 1.9.40): тема → фон,
  green → изумруд, violet → фиолетовый, blue или ничего → синий. Старые ключи не стираются.
- `on-accent`: ТЗ обещает, что белый или #0B0D12 всегда дают ≥ 4,58 : 1 — для средне-серых
  это неверно (#777777: 4,48). Запасной вариант — чистый чёрный, он гарантирует ≥ 4,5.
- Пресеты (утверждены владельцем 4 окт 2026): синий #2F62EA, фиолетовый #7357F0, изумруд
  #0E9B72, бирюзовый #0E8FA6, розовый #D6407F, оранжевый #E8640C, жёлтый #F2C230, графит #4D5566.
- Контраст проверяется временным скриптом на всех трёх фонах (`node --experimental-strip-types`
  с загрузчиком, добавляющим `.ts` к относительным импортам) — потому `colors.ts` и
  `appearanceModel.ts` без импортов React Native.
- Шрифт прежних вкладок — `src/OnestText.tsx`: импорт `Text`/`TextInput` оттуда, а не из
  `react-native`. Начертание берётся из `fontWeight`, вёрстка не меняется.
- Виджет на рабочем столе и строка «идёт пара» (Kotlin) с 1.9.47 тоже берут акцент и фон —
  см. «Виджет «Табло» и его цвета».
- **Применение в два шага** (`src/appearance.ts`): «выбранное» меняется сразу (кольцо выбора
  на экране), «применённое» — следующим кадром; быстрые тапы схлопываются, запись в хранилище
  одна, через 400 мс. Смена фона — сразу (`immediate`), у неё своё растворение (ThemeReveal).
- **`freezeOnBlur: true`** у вкладок: скрытая вкладка не перерисовывается, пока её не откроют.
  Иначе смена акцента перекрашивала разом все открытые вкладки.
- **Экран «Внешний вид» без измерений раскладки.** В 1.9.40 предпросмотр брал высоту из
  `onLayout` → `setState`, внутри тикал отсчёт и пульсировала точка — владелец видел, как
  экран мелко дрожит. Теперь размеры — целые числа из ширины окна, высота карточки —
  константа, карточка неподвижна (`stillAt` у `FocusCard`), шрифт внутри не масштабируется
  (`FixedFontScale`). Не возвращать `onLayout` → `setState` в предпросмотр.
- **Нижние листы (`BottomSheet`) — без `KeyboardAvoidingView`.** В режиме `'height'` он
  считает свою высоту от собственного измерения; после клавиатуры на листе Android
  округлял размеры то вверх, то вниз, и лист «трясся» (лист пары, лист аудитории, 1.9.41).
  Отступ под клавиатуру теперь считается один раз на событие клавиатуры от рамки окна.
  Общее правило: **не задавать размер элемента из его же `onLayout`** — только константы,
  ширина окна или запись в `ref`.
- «Свой цвет» — квадрат насыщенность × яркость и ползунок оттенка (`src/settings/ColorPicker.tsx`,
  react-native-svg + PanResponder). При перетаскивании меняется только состояние листа.
- **Плотность**: по ТЗ компактная была 52/7 против 60/10, но высоту строки пары задаёт
  содержимое (три строки в колонке времени), и разница выходила ~8 %. Сейчас:

  | | обычная | компактная |
  |---|---|---|
  | строка пары (предмет в одну строку) | 74 dp | 52 dp (поля 4, «11:15 · II» одной строкой) |
  | строка аудитории | 56 dp | 48 dp (минимум зоны нажатия) |

## Виджет «Расписание», вариант C «Аудитория» (`native-widget/`, с 1.9.48)

По ТЗ `widget-C-TZ.md` и макету `widget-C-maket.png` (Claude Design), принят владельцем
4 окт 2026. Номер аудитории — самый крупный элемент, цвет виджета — статус пары, под шапкой
сетка следующих пар 2 × N. Один виджет, тянется по ширине и высоте (второго «большого»
в списке виджетов нет — решение владельца). Вариант 1.9.47 (карточка «Табло») заменён:
большой виджет растягивался, а содержимое — нет.

**Раскладки по высоте H** (`ScheduleWidget.kt` выбирает сам):

| H, dp | Раскладка | Файл |
|---|---|---|
| < 170 | малая: шапка по центру, без сетки | `widget_compact.xml` |
| 170–244 | компактная: шапка 44 dp + сетка | `widget_compact.xml` |
| ≥ 245 | полная: строка статуса, шапка 56 dp + сетка | `widget_full.xml` |

- **Сетка** (ТЗ 2.3, функция `gridFor`): `avail = H − top − hero − 10 − 12 − 1`,
  `minRow = max(44, ⌈34·f⌉ + 10)`, `N = min(6, ⌊avail/minRow⌋, ⌈пар/2⌉)`, ряд ≤ 60 dp,
  остаток — в распорку над сеткой. Строка шапки не ниже блока отсчёта (`max(44, 28 + 14·f)`),
  иначе при ×1,3 срезалась бы подпись. Проверено скриптом на 160/200/240/250/320/380 при
  f = 1 и 1,3 (таблица ТЗ совпадает с точностью до округления: 44,6 → «45»).
- **Android 12+**: лаунчер даёт все размеры (`OPTION_APPWIDGET_SIZES`) — по раскладке на
  каждый (`RemoteViews(Map<SizeF, RemoteViews>)`), высоты рядов — `setViewLayoutHeight`.
  **Старые**: размер по ориентации (портрет — MIN_WIDTH × MAX_HEIGHT), ряды по 44 dp из
  разметки. Остаток высоты всегда у распорки над сеткой (`layout_weight`): у RemoteViews
  нет `setViewLayoutWeight`, поэтому вес задан в разметке раз и навсегда.
- Нет следующих пар (N = 0) — шапка по центру, как у малой, без пустоты внизу.
- **Масштаб под размер** (2.0.2, решение владельца: на крупных ячейках Xiaomi было мелко и
  пусто). `plan()`: число рядов — сколько помещается при масштабе 1 (поэтому сетка видна
  примерно с 160 dp, а не строго с 170); затем масштаб s = ширина/280, не больше ×1,25, —
  самый крупный, который не отнимает ни одного ряда. Без рядов — шапка по центру, s — пока
  влезает по высоте. На s умножаются все шрифты, шапка (`widget_hero`, точная высота) и
  ряды; только Android 12+, на старых s = 1. При ширине 280 — ровно таблица ТЗ.
- `widget_full.xml` и `widget_compact.xml` пишет `node native-widget/gen-layouts.js` (общие id).
  Крупные цифры — в dp (не растут со шрифтом), остальное — в sp. Только классы RemoteViews:
  простой `<View>` лаунчер не покажет («Не удалось загрузить виджет»).
- **Аудитория** 56/44 dp, длиннее 4 знаков — 32; не влезает рядом с отсчётом — код уменьшает
  по замеру (`Paint.measureText`), но не ниже 20 dp. Отсчёт резервирует место под «0:00:00».
- **Шрифт системный**: свои шрифты (Onest) лаунчер в виджете не грузит.

**Состояния** (ТЗ 5.1 с решениями владельца Д1–Д4, 4 окт 2026):

|---|---|---|---|
| Идёт пара | идёт | «Идёт · II пара», отсчёт до конца | fill |
| Перемена | сегодня пара уже была и ещё будет — **любой** промежуток, и обед (Д1, без порога 20 мин) | «Перемена · III пара», отсчёт на плашке fill | soft |

| Неделя не вышла | пар впереди нет, следующей недели ещё нет (Д4) | «Пар больше нет», «Следующая неделя ещё не опубликована» | tint |
| Не загружено | нет `widget_data` | «Расписание не загружено», «Нажмите, чтобы обновить» | tint |

`tint` вместо белого `surface` — с 2.0.2 (владелец: «не прям белым, а цветом акцента»).

Слово «окно» не используется нигде (решение владельца): до 20 минут — «перемена», дольше —
«перерыв» (`BREAK_MAX_MIN` в `src/api.ts`, `gapLabel` в `src/schedule/state.ts`); в плашке
Расписания любой промежуток после пары — «Перемена · N пара».

**Данные** (`src/widgetData.ts`, ключ `widget_data`): эта неделя + следующая из кэша
(`cache_weeks_<группа>` → `cache_schedule_<группа>_<id>`), `nextWeekPublished`. У пары:
`pair`, `type` (подпись «Лекция»), `teacher` (как пришёл), `room` — уже через `displayRoom`
(«лабхим» → «Лаб. химии», как на вкладке «Аудитории»). Группа — `shortGroupName`.

**Цвета** — роли ТЗ 4.1, считает JS (`src/widgetThemeModel.ts`), Kotlin только выбирает набор:

| Роль | Откуда |
|---|---|
| surface, ink, ink2, line | surface, text, text-secondary, border фона |
| fill, onFill, soft, onSoft, accentText | accent, on-accent, accent-soft, on-accent-soft, accent-text |
| onFill2 | самая тихая смесь onFill → fill (≤ 15 %), держащая 4,5 : 1 |
| fillLine | fill + 20 % onFill |
| softLine | soft + 18 % fill |
| tint | surface + 8 % / 10 % / 9 % акцента (светлый / тёмный / чёрный) — светлее soft |
| tintLine | tint + 18 % fill |
| ink3 | ink2 + 25 % tint, доведённый до 4,5 : 1 к tint |
| accentText | accent-text, доведённый до 4,5 : 1 к tint |

- Ключ `widget_theme` (`version: 3` с 2.0.2: добавлены tint, tintLine) — три фона приложения (светлый, тёмный, **чёрный**).
  Пишет `src/widgetTheme.ts` при запуске и после каждой смены оформления, затем будит
  виджет и строку «идёт пара». Отдельный ключ, а не `widget_data`: «Внешний вид» не знает пар.
- «Как в системе» на Android 12+ — `setColorInt(светлый, тёмный)`, лаунчер переключает сам;
  на старых — по теме в момент обновления.
- Подложки — белые картинки (`widget_bg` 24 dp, на Android 12+ системное скругление из
  `drawable-v31`; `widget_plate` 10 dp), красит `setColorFilter`; линии — `setBackgroundColor`.
- Нет ключа или он старый (1.9.47 — другие имена ролей, до 2.0.2 — без tint) — синий по умолчанию: `DEFAULT_THEME` в
  `ScheduleWidget.kt` = вывод `widgetTheme(DEFAULT_APPEARANCE)`. Сменили синий или формулы —
  обновить (временный скрипт сверяет).
- Контраст проверен скриптом на 8 акцентах, «своих» #777777/#FFFFFF/#000000/#FFFF00/#123456 и
  трёх фонах: всё ≥ 4,5 : 1.

**Обновление**: на границах пар и в 00:00 (будильник `WIDGET_TICK`), при открытии приложения
и загрузке расписания (`refreshWidget`), при смене оформления, при изменении размера
(`onAppWidgetOptionsChanged`), раз в 30 мин системой. Сначала пересчитывается состояние, потом
отсчёт. Будильник — `setExactAndAllowWhileIdle`; если Android 12+ не разрешает точный
(`canScheduleExactAlarms` / `SecurityException`) — `setWindow` с окном в минуту. Так же в `LiveLesson.kt`.

**Отсчёт** — системный Chronometer («42:13», «1:05:09»), подпись «до конца / до начала»
отдельной строкой. Никакого обычного текста, похожего на живой отсчёт (шапка `ScheduleWidget.kt`).
Нажатие в любом месте — `msu-schedule:///` в `MainActivity`: expo-router открывает «Расписание».

`schedule_widget_info.xml`: 4×2 по умолчанию, `minWidth` 250, `minHeight`/`minResizeHeight` 100,
`previewLayout` (Android 12+) и `previewImage` (картинка, вырезанная из макета).

## Строка «идёт пара» (`modules/live-lesson/`)

Локальный нативный модуль на Kotlin. Показывает текущую пару с живым отсчётом, а на
**Android 16** просится отдельной плашкой прямо в статус-бар (флаг
`FLAG_PROMOTED_ONGOING` + `setShortCriticalText`; на старых версиях эти вызовы
пропускаются по `Build.VERSION.SDK_INT >= 36`, иначе был бы `NoSuchMethodError`).

Почему работает без запущенного приложения:

- расписание уже лежит в AsyncStorage под ключом `widget_data` (пишет `src/widgetData.ts`
  для виджета) — Kotlin читает базу `RKStorage` напрямую;
- отсчёт рисует сам Android (`setUsesChronometer` + `setChronometerCountDown`), поэтому
  раз в минуту будить приложение не нужно;
- будильник ставится ровно на границу пары — 5–10 раз в день,
  `setExactAndAllowWhileIdle`; если Android 12+ точный не разрешает — `setWindow` с окном
  в минуту;
- пары в шторке — цветом акцента из `widget_theme` (роль `fill`);
- после перезагрузки телефона и обновления приложения будильник переподнимает
  `LiveLessonReceiver` (`BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`);
- страховка от Doze — `refreshLiveLesson()` при каждом возврате в приложение (`_layout.tsx`).

⚠️ **Копировать в `android/` не нужно.** Модуль подхватывает автолинковка
(`useExpoModules()` в `settings.gradle`), а манифест библиотеки склеивается с манифестом
приложения сам — `expo prebuild` его не стирает. В этом его отличие от виджета.

В `modules/live-lesson/android/build.gradle` обязательны `versionCode` и `versionName`
внутри `defaultConfig` — без них конфигурация Gradle падает с
«android.defaultConfig.versionName is not defined».

Виджет и эта строка кормятся **только своей группой, текущей неделей и следующей** (если она
вышла и лежит в кэше) — иначе
достаточно было заглянуть в архив или в расписание другой группы, чтобы они показывали
чужое (см. `feedDevice` в `src/schedule/ScheduleScreen.tsx`).

## Загрузка для работы без интернета (`src/offline/`, с 2.0.3)

Просьба владельца (6 окт 2026): попросить подождать, пока скачается всё нужное для работы без
интернета, и **докачивать каждый раз, пока не скачано до конца** — не только при первом входе.
Раньше та же загрузка шла молча в фоне, и человек не знал, закончилась ли она.

- Экран — сразу после онбординга («Скачиваем расписание») и **при каждом холодном запуске**, если
  `isOfflineDataComplete()` говорит, что чего-то нет («Докачиваем расписание»).
- **Что значит «всё»** (`missingParts`, то же, что кладёт bulk-sync): была полная загрузка и не
  оборвалась на записи (метка `sync_incomplete` стоит от начала записи до конца), список групп,
  все недели своей группы с расписанием, педагоги — список и расписание каждого — и аудитории по
  6 дням × 5 пар на эту и следующую неделю (`syncWeeks` — как на сервере). Чужие группы
  поштучно не проверяются: они приходят тем же ответом.
- **Не мучаем зря**: полная загрузка прошла до конца меньше 4 ч назад — считаем, что всё есть
  (чего не хватает и тут, докачка не даст); своей группы нет в списке групп — её недели не требуем.
- Загрузка — обычный `triggerSync()` (bulk-sync), без отдельного запроса. `performFullSync`
  **одна на всё приложение**: второй вызов присоединяется к идущей (фоновая на старте, push,
  кнопка в Кабинете), а не качает заново. Этапы — события `SyncStage`: `download` →
  `groups` → `teachers` → `rooms` (запись в хранилище тремя частями, по ним и галочки);
  пятый этап — история своей группы (`prefetchMyChanges`), её ошибка не считается провалом.
- Итог «24 группы · 85 педагогов · 40 аудиторий» — из того же ответа (`SyncSummary`).
- Вверху — иконка приложения с крутящимся кольцом (`LoaderIcon.tsx`, вернули прежний `AppLoader`
  по просьбе владельца): готово — кольцо целиком цветом и галочка, ошибка — серое и «нет сети».
- Ответа нет 10 с — подсказка «Сервер просыпается» и кнопка «Не ждать — докачается само».
- Ошибка — «Повторить» / «Позже»; вернулась сеть — повтор сам. Пока не докачано, в Кабинете под
  профилем карточка «Расписание скачано не полностью · Докачать» (та же проверка, на входе во
  вкладку и после каждой синхронизации).
- Логика проверена временным скриптом на синтетических данных (30 случаев, включая хранилище в памяти).

## Кэш и сеть

**Экраны рисуются из кэша, потом молча обновляются.** Раньше было наоборот: сначала
запрос, и только когда он упадёт (15 секунд тайм-аута, а на спящем Render дольше) —
чтение с диска. Пользователь смотрел на спиннер, хотя данные уже лежали в AsyncStorage.

Ключи AsyncStorage — те же, что заполняет полная синхронизация (`syncService.ts`),
поэтому кэш общий и заполняется заранее:

| Ключ | Что |
|---|---|
| `cache_groups`, `cache_weeks_all`, `cache_weeks_<groupId>` | списки |
| `cache_schedule_<groupId>_<weekId>` | расписание группы |
| `cache_teachers_<weekStart>`, `cache_teacher_<id>_<weekStart>` | преподаватели |
| `cache_rooms_<day>_<pair>_<weekStart>` | свободные аудитории |
| `cache_changes_<groupId|all>` | лента изменений |

- Полная синхронизация — **один** запрос `/api/schedule/bulk-sync`, стартует через
  3 секунды после запуска, чтобы не отбирать канал у первого экрана.
- `src/api.ts` дедуплицирует одинаковые пути: три экрана, спросившие список групп
  одновременно, дают один запрос.
- **Состояние сети — событие от Android** (`@react-native-community/netinfo`,
  `NET_CAPABILITY_VALIDATED`), своих запросов ноль. `reachabilityUrl` в
  `SyncContext.tsx` — только запасной путь, если система не дала ответа.
- **«Сеть вернулась» — только через `useOnlineAgain()`** (`SyncContext.tsx`), не `useEffect` на
  `onlineAt`. `onlineAt` растёт и после каждой ручной синхронизации (экран загрузки, Кабинет), и
  экран, открытый позже, видел его не нулём уже на первом кадре: тихий сетевой запрос перебивал
  показ кэша (`reqRef`), и без сети «Педагоги» / педагог / «Аудитории» писали «Нет подключения»,
  хотя всё скачано (найдено владельцем 6 окт 2026, исправлено во всех четырёх экранах).
- **Показ кэша не отменяется тихим запросом** («Педагоги», педагог, «Аудитории»): у кэша свой
  счётчик (`paintRef`), отменяют его только более новое чтение кэша или ответ сети на тот же
  день/неделю. Раньше любой `load(true)` (сигнал сети, «список пуст, а синхронизация была»)
  делал чтение кэша устаревшим, и без сети экран оставался пустым.
- Неделя «прилипает» к выбранной пользователем только после того, как он сам нажал
  кнопку недели (`userPickedWeekRef`). Иначе неделя всегда пересчитывается по
  сегодняшней дате — чтобы кэш недельной давности не удерживал экран на прошлой неделе.

## Кэш на телефоне и ошибка SQLITE_FULL (с 1.9.46)

Ключи кэша расписания содержат номера записей сервера (`cache_schedule_<группа>_<id недели>`,
`cache_teacher_<id педагога>_<неделя>`). После пересборки базы или правки файла номера новые,
а старые ключи раньше оставались навсегда. Хранилище AsyncStorage на Android ограничено ~6 МБ:
оно переполнилось, и полная синхронизация молча падала с «database or disk is full (code 13
SQLITE_FULL)» — «Последнее обновление» в Кабинете замерло, остальные экраны жили на своих
запросах. Теперь `performFullSync` перед записью удаляет все `cache_*`, которых нет в свежем
ответе (кроме метки времени и `cache_changes_*`), а при ошибке записи чистит кэш целиком и
пишет заново. Причина сбоя синхронизации видна в Кабинете рядом с «Не удалось обновить».
